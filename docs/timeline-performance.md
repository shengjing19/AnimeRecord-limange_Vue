# 时间线模式性能优化

## 原因与改动

- 原实现挂载全部月份，入场还为全部月份创建动画。现在只保留当前月份前后各六个节点，整条轨道通过原生 Web Animations API 移动，不再逐帧遍历月份。
- 卡片切换通过 Anime.js 在主线程计算多项 3D 属性，并反复查询元素、写入层级。现在由 CSS 对 `transform` 和 `opacity` 插值；相邻切换保留六张卡片，跨月复用相同索引的按钮和合成图层。
- 时间线原先直接加载完整封面，没有使用首页已有的后台缩图、并发限制和缓存。现在复用共享管线，桌面封面为 512px，高像素密度为 768px；移动布局使用 384px 或 512px。中心及最近两侧优先加载，远侧延迟 180ms，持续切换时取消过时任务。
- 进度条的宽度动画、活动月份字号变化和圆点尺寸动画原先会触发布局。现在分别使用 `scaleX`、文字缩放和固定尺寸圆点的缩放，移除简介面板的实时背景模糊和入场裁剪。
- 简介与统计直接派生自当前选择，取消等待淡出回调后更新数据的流程，快速点击不会积压旧内容。归档数据使用 `shallowRef`，只在响应返回时整体替换。
- 系统和应用的减少动态效果设置均可生效；卸载清理动画、延迟任务、图片引用和事件监听。重试完成后恢复场景焦点，保证 Esc 和方向键继续可用。

## 固定负载结果

2026-11-12，在 Edge 无头浏览器、1696 × 1028 视口、4 倍 CPU 降速下测量。数据包含 120 个月、1200 条记录和 1600px 独立封面地址；每 110ms 切换一次，共 24 次，随后等待动画结束。结果不代表所有设备的帧率。

| 指标                         |   优化前 |   优化后 |
| ---------------------------- | -------: | -------: |
| 月份切换 P95 帧间隔          |   66.7ms |   33.3ms |
| 月份切换最长帧间隔           |  383.4ms |   49.9ms |
| 月份切换超过 33.4ms 的帧     | 44 / 126 |  7 / 203 |
| 月份切换长任务数（≥50ms）    |        4 |        0 |
| 同月卡片切换 P95 帧间隔      |   17.1ms |   17.1ms |
| 同月卡片切换 JavaScript 时间 |  338.0ms |   80.6ms |
| 同月卡片切换主线程任务时间   | 2417.3ms | 1328.7ms |
| 同月卡片切换样式属性写入     |     4310 |      456 |
| 挂载月份节点                 |      120 |       13 |
| 挂载封面卡片                 |        7 |        7 |

此场景中原版同月卡片切换已经接近 60Hz，因此不能据此声称卡片帧率提升。改善体现在约 76% 的 JavaScript 时间下降、约 45% 的主线程任务时间下降，以及大图纹理占用的减少。缩图加载会产生独立布局任务，月份布局次数没有下降；优化重点是避免这些任务与每帧脚本、全列表动画和大纹理上传集中发生。

## 复测

运行 `npm run test:timeline`。脚本使用独立本地服务，不访问用户数据，结果保存在 `.temp/qa/timeline-after.json`，桌面与移动截图也保存在该目录。

比较旧实现时，先将旧版 `AnimeTimelineMode.vue` 保存为 `.temp/qa/AnimeTimelineMode.before.vue`，再运行 `npm run test:timeline -- --baseline`。Vite 测试插件只替换该组件的加载源，无需修改当前工作文件。运行 `npm run test:timeline -- --trace` 可输出 Chromium 追踪文件；性能比较时不要同时运行构建或其他浏览器测试。

自动验证还覆盖一部、两部、四部作品的月份、循环与快速输入、真实鼠标滚轮、移动布局、CORS 与坏图回退、减少动态效果、错误重试和加载途中关闭。布局单元测试验证万条记录下的窗口边界；Electron 冒烟测试验证桌面协议中的 Worker 缩图和卡片切换。
